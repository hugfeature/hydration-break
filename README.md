# 休息与运动 / Rest & Move

离线喝水与办公室活动提醒，支持 Android 与 Windows。无账号、服务器、广告、分析 SDK。

## 下载
- Android：Actions → Build Android APK → 最新成功运行 → rest-and-move-0.2.0-android。
- Windows：Actions → Build Windows desktop → 最新成功运行 → rest-and-move-0.2.0-windows-x64。
- 仓库私有时，Actions 下载需要仓库访问权限；可下载后将 APK / setup.exe / portable.zip 直接转发。没有公开源代码或更改仓库可见性。
- 只使用测试通过的产物，包内有 SHA256SUMS、使用说明和隐私说明。

## 功能
- 喝水、运动独立开关与间隔；每日提醒时段。
- 7 个办公室小幅动作，可预览、选择或全部排除；两端共用离线动作目录。
- Android：首页保留下一次提醒和必要权限提示，测试入口在“设置与帮助 → 提醒诊断”。
- Windows：托盘运行、暂停 30 分钟、恢复提醒；关闭窗口不退出，托盘菜单可以退出。

## 构建
Android：JDK 17 + SDK 35 + Gradle 8.10.2，gradle assembleRelease。
CI 从已有 Secret 恢复固定签名；release 非 debuggable，并验证从真实 0.1.5 代码构建的旧包覆盖升级保留设置。未配置密钥则失败。
Windows：.NET 10 SDK，dotnet publish windows/RestAndMove.csproj -c Release -r win-x64 --self-contained true。
安装包由 Inno Setup 6 构建；运行时自包含，无需用户安装 .NET。尚无 Windows 发布者签名证书。

## 边界
Android 精确闹钟需要用户授权；未授权降级并提示。系统强行停止后需手动重新打开；开机恢复在解锁后。厂商后台限制和通知可见性仍需真机检查。
Windows 不默认开机启动，不唤醒睡眠电脑；睡眠恢复重新计时，不集中补发。勿扰或锁屏策略可能隐藏系统通知。
暂不支持跨午夜时段、按星期配置、账号同步或喝水量统计。
自动构建、模拟器送达与目标设备实测是不同验证项，不能互相替代。

## 历史变更（以下描述只适用于对应旧版本）
## 本轮修复与验证范围（0.1.1）
- 首次启动即调度默认提醒；再次启动保留未来到期时间。
- 时段先校验后整体保存，无效输入不会取消已有提醒；独立开关、间隔立即生效。
- 显示通知/通知类别关闭状态，提供系统通知设置入口；处理通知权限撤销与闹钟权限异常。
- CI 增加计算边界单测、Android 15 仪器测试、APK 签名校验与实际安装/启动检查。
- 模拟器脚本检查后台、锁屏/Doze 下闹钟仍注册，以及实际重启后的重新注册和通知权限状态。
- 接收器通知测试是直接调用接收器，**不代表定时投递通过**；Doze 注册检查也不代表通知按时送达。
- CI 的真实结果以该提交 Actions 日志及 validation-reports 为准；失败步骤不能视为通过。

## 真机验收（尚未执行）
1. 设置喝水 15 分钟、休息 30 分钟，时段覆盖当前时间，分别关闭一个提醒检查互不影响。
2. 分别前台、切后台、锁屏、开启省电模式，记录计划时间/实际通知时间；至少观察两个提醒周期。
3. 修改间隔及有效时段检查后续提醒；输入无效时段确认旧设置保留。
4. 重启并解锁手机，不打开 App，检查后续提醒；强行停止后重新打开检查恢复。
5. 拒绝/撤销通知权限、关闭通知类别，再重新开启，检查状态提示及后续提醒。
6. 在目标手机离线安装并运行；不同 CI 构建覆盖安装与稳定签名尚未验证。

## 0.1.2：手机端诊断与版本识别
- 首页显示版本号；如果仍看到“保存并启用提醒”且没有“通知设置”，请核对是否安装了早期 APK。
- 显示当前时段、下一次计划、最近系统触发及通知提交/阻止原因。计划时间不是准时送达承诺。
- “立即发送测试通知”检查通知权限和通知栏；“安排锁屏测试”使用同一非精确闹钟 API，约一分钟后单次通知，不受每日时段限制，不改变正常提醒。
- CI 的锁屏测试采用 1 秒测试延迟，在真实 Doze 状态等候接收器与系统通知，最多 120 秒。它验证模拟器投递链路，不能替代目标手机的 30/45 分钟长期测试。
- APK 文件名包含版本号。原提醒时段仍是 09:00–18:00；晚间测试使用单独按钮，或主动调整结束时间并保存。

## 0.1.3：休息与运动
- 桌面名称和首页改为“休息与运动”，包名、设置键和调度方式保持兼容；喝水与运动独立配置。
- 每次成功提交通知后轮换一个办公室小幅动作：坐姿抬膝、轻转肩背、缓慢转头。通知展开显示步骤，点击打开对应动作；首页可随时浏览、换动作。
- 动作内容完全离线，参考 [NHS 坐姿活动](https://www.nhs.uk/live-well/exercise/sitting-exercises/)，按办公室小幅活动场景简化。使用稳固无轮椅子，轻缓进行，不适即停；不是个体化康复处方。
- 未增加权限。仍使用 CI 调试签名，旧版可能无法覆盖安装；卸载重装会清空设置。

## 0.1.4：固定签名（需先配置一次）
CI 必须读取仓库 Secret `ANDROID_SIGNING_JSON`；未配置时明确失败，不再生成新的随机签名 APK。密钥不进入代码、缓存或构建产物。调试构建类型暂时保留，便于现有诊断；固定签名不代表已改为正式发布版。

仓库所有者在装有 JDK 17、Python 3 和 GitHub CLI 的电脑上执行：
```bash
gh auth login
git clone https://github.com/hugfeature/hydration-break.git
cd hydration-break
python3 scripts/configure-signing.py ~/hydration-break-signing-backup
gh workflow run android.yml -R hugfeature/hydration-break
```
已有 checkout 则先更新，不必再次 clone。脚本生成长期密钥并通过 stdin 上传到 GitHub Secret；本机目录保留唯一可导出的备份，请安全另存一份。上传失败可用同一个目录重试；Secret 已存在时拒绝替换，避免意外改变应用身份。不要将备份发到聊天或提交 Git。

旧流程没有保存调试私钥，APK 只包含证书，不能从 APK 还原私钥。找不到旧密钥时，旧随机签名版转到固定签名版仍需一次卸载重装，此后应在同一密钥下递增版本覆盖安装。

CI 新增两次独立 clean 构建的证书一致性检查，以及低版本安装→写入非默认设置→`adb install -r` 高版本→设置保留检查。仅在配置 Secret 且实际运行通过后，才能报告覆盖安装验证通过；它不证明旧随机签名版可以直接升级，也不替代手机端验证。


## 0.1.5：精确提醒与过期恢复
- 新增 SCHEDULE_EXACT_ALARM 特殊访问权限，由用户在系统设置授权。授权后使用 setExactAndAllowWhileIdle；未授权或授权竞态失败时降级普通提醒，并明确显示无法保证一个周期内送达。
- 打开页面、重启和覆盖更新保留未来计划；提醒时段内的过期计划按单次补发恢复，不重新等待完整周期。不变的时段保存不会重置倒计时。
- 首页显示调度模式、上次原计划、实际触发及延迟；通知提交成功不代表用户已经看到。
- 自动化增加正式喝水/运动 15 分钟计时后在锁屏 Doze 下验证送达；测试进程仍存活，不能替代手机厂商后台清理与连续多个周期验证。
- 精确提醒仍可能受系统节流和厂商限制；需要真机验证“延迟少于一个周期，且无需亮屏”。固定签名沿用 0.1.4，可覆盖安装。
